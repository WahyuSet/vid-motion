# AGENTS.md — vid-motion

Guide for AI agents that make videos with this repo. Read it fully before your first video.

## What this repo makes

Vertical **YouTube Shorts (1080×1920, 30 fps, 40–60 s)** in **Indonesian** for three channels.
Every frame is drawn as SVG in a headless browser from code, voiced by TTS, and encoded with ffmpeg.
Nothing is downloaded or generated by an image model: all visuals are drawn by you in `scenes.js`.

## Channels — read the channel's RULES.md before any task

| channel (`script.json` → `"channel"`) | mascot | theme | topics |
|---|---|---|---|
| `cicaktahu` — **Cicak Tahu** (`@cicaktahu`), default | Si Cicak (`cicak`, flat ink) | `paper`: warm paper, outlined titles, yellow marker captions | fakta unik, mitos atau fakta, everyday science |
| `tikus` — name not chosen yet | Si Tikus (`tikus`, soft plush) | `newsprint`: newspaper grey, condensed titles on white strips with a red edge, navy lower-third captions, red label stamps | politics, government, personal finance, economy, investment education |
| `stickman` — name not chosen yet | Stickman (`stickman`, doodle) | `notebook`: ruled page with a red margin, handwritten titles and captions, highlighter, circled-word stamps | health, the human body, education |

Each `channels/<id>/` holds `channel.json` (name, handle, tagline, mascot, theme, topics, watermark) and
**`RULES.md`: that channel's scope and content rules, which are stricter than this file and win over it**
(politics must be non-partisan, finance is education-only with an OJK disclaimer, health is general information
with a doctor disclaimer). Use only that channel's mascot and draw props in its art style. The theme is applied
automatically from the channel. Mention the channel by name in metadata (description sign-off), never in the hook.
`topics/demo-tikus` and `topics/demo-stickman` are short working examples of the two newer themes.
`topics/demo-cicak` shows the data card, scramble, sound stickers, x-ray lens, cutaway and pill captions.

## Commands

```bash
python build_video.py <topic> preview              # stills at the middle/end of every scene -> build/<topic>/preview.png
python build_video.py <topic> preview 3.5,12.8     # stills at chosen seconds
python build_video.py <topic>                      # full render -> output/<topic>.mp4
python build_video.py <topic> thumb                # output/<topic>-thumbnail.jpg (needs drawThumbnail)
python build_video.py <topic> check                # retention warnings: hook, pauses, silences, static stretches
python build_video.py <topic> narasi               # output/<topic>-narasi.json: clean narration to voice outside
python build_video.py <topic> workers=2            # fewer parallel browsers on small machines
```

Videos render at 60 fps: a full 50 s render takes about 4–5 minutes with 6 workers on 12 cores (`"fps": 30`
halves that while iterating); scale expectations to the machine.
Always iterate with `preview` (seconds) before a full render, and run `check` before it: fix every warning or
know why it is fine.

## Tasks (skills) and approval gates

Each task has a skill with the detailed steps. **Read the skill's `SKILL.md` before doing that task.**

| task | skill | needs status | ends with status |
|---|---|---|---|
| find and propose ideas | `skills/cari-ide/SKILL.md` | — | `usulan` |
| research + write the script | `skills/tulis-naskah/SKILL.md` | `disetujui` | `naskah` |
| animate, render, metadata | `skills/buat-video/SKILL.md` | `naskah-ok` | `video` |
| thumbnail | `skills/buat-thumbnail/SKILL.md` | a working `scenes.js` | — |

Progress lives in **`ideas.md`**. The statuses `disetujui`, `naskah-ok`, `siap-upload` and `ditolak` are set
**only by the human**: never move an idea past one of them yourself. Ask with `request_user_input`, or in an
unattended run stop and report. Each task touches only its own topic folder plus `ideas.md`.

Per topic, the files are: `topics/<id>/sources.md` (claim → source), `script.json`, `plan.md` (beat plan),
`scenes.js`, `meta.md` (title, description, hashtags); `voice/` only for own recordings.

## Workflow for a new video (summary)

1. **Pick and verify the facts.** Only use claims you can back with a reputable source
   (journals, government/health agencies, encyclopedias, established institutions). Write the sources down;
   they go on screen (`cite`) and in the video description. Drop any claim you cannot verify.
   No medical, financial or legal advice beyond general, well-established information.
2. **Write `topics/<topic>/script.json`** (schema below). Aim for 9–11 lines, ~90 words total, 45–55 s.
3. **Run `preview` once** with an empty-ish `scenes.js` (see "minimal paper topic") to synthesize the voice
   and get word timings in `build/<topic>/tts/scene*.json`. Every visual beat is anchored to a spoken word.
4. **Write `topics/<topic>/scenes.js`** in paper style (API below). Copy patterns from
   `topics/burung-listrik/scenes.js`, the reference implementation.
5. **Check stills** at every important moment (`preview a,b,c`): headline handoffs, stamps, reveals,
   first frame, last frame. Look at the images. Fix overlaps, empty frames, unreadable text.
6. **Full render**, then **thumbnail**.
7. **Deliver**: `output/<topic>.mp4`, `output/<topic>-thumbnail.jpg`, and `topics/<topic>/meta.md`.

## Content rules

- Story formula (proven by the reference channels):
  1. **Hook in the first 2 s**: a question or a surprising claim, visual immediately ("Kok bisa?").
  2. **The common belief**, then **bust or confirm it** with a `stamp('MITOS!')` / `stamp('FAKTA!', …, C.leaf)` and
     Si Cicak's `verdict` pose.
  3. **Mechanism**, explained with one simple visual idea (analogy, diagram, comparison card).
  4. **Proof / consequence**: an experiment, a number with its source, a real-world example.
  5. **Synthesis**: one sentence the viewer can repeat ("Satu kabel = aman"), with the chapter recap row.
  6. **Local takeaway or safety tip**, then **loop**: the last camera view equals the first one.
- Tone: casual spoken Indonesian ("kamu", "kok", "ya"), short sentences, no jargon without explanation.
- Prefer **local references**: PLN, Jakarta, Kebun Raya Bogor, Jawa Barat, layangan, Indonesian animals.
- Mark 1–2 **keywords per line** with `*stars*` in the script; they get a yellow marker in the captions.
- Write numbers the way they should be read and check the TTS reads them right
  (`build/<topic>/tts/scene*.json` shows what was spoken). "20.000 volt" works with the default voice.
- Never copy another channel's script, topic angle or artwork. Style inspiration only.

need it, and re-check old topics with `preview` afterwards.

## script.json

```json
{
  "style": "paper",
  "captions": {"words": 6, "line": 34},
  "tail": 1.6,
  "voice": {"provider": "edge", "name": "id-ID-GadisNeural", "rate": "+12%"},
  "scenes": [
    {"vo": "Kabel listrik ini bertegangan *20.000 volt*."},
    {"vo": "Listrik hanya mengalir kalau ada *beda tegangan*.", "hold": 0.9}
  ]
}
```

- One entry per voice-over line. The pipeline inserts 0.35 s of silence between lines. The TTS stops about 1 s
  after "." "?" "!" inside a line; those pauses are cut to 0.35 s automatically (`"pause": s` changes the
  limit, `0` keeps them). Prefer one sentence per line anyway: it paces captions and headlines better.
- `hold`: extra seconds after a line so an animation can finish (cards, explosions, reveals).
- `tail`: seconds after the last line (use ~1.6 for the loop back to the opening view). With the end card on,
  the tail is at least 2.4 s.
- `voice`: see `tts.py`. Default is fine. `TTS_PROVIDER` / `TTS_VOICE` env vars override it.
- `channel`: `cicaktahu` (default), `tikus` or `stickman`; it sets the theme, mascot and watermark.
- `captions`: `"words": 5` recommended. `"size": N` overrides theme caption size. `"line"` is mostly irrelevant now that captions re-wrap automatically in JS.
  `"mode": "pill"` puts every caption line on a dark pill with a yellow box sliding behind the spoken word
  (spoken keywords turn yellow). Use it when the picture behind the captions is busy (circuits, maps, crowds);
  leave it out to keep the channel's own caption look.
- `progress`: `true` shows a progress bar at the top (off by default).
- `fps`: 60 by default (smoother motion); 30 renders twice as fast.
- `music`: a quiet, original music bed made by the pipeline (pad, bass, plucked arpeggio; mood per theme) runs
  under every paper-style video and ducks while the voice speaks, so there is no dead silence. `false` switches it
  off; a path (relative to the topic folder) uses your own track instead, looped (you are responsible for its rights).
- `outro`: end card shown from 0.25 s after the last word, fading out 0.25 s before the end so the loop stays
  seamless: "Thank you for watching!" plus the channel handle, in the theme's title style. Default text comes
  from the engine or `channel.json` → `"outro"`; `"outro": ""` switches it off. Keep the last line's visuals
  finished before it (the card dims the picture).
- `watermark`: leave it out; the handle from the channel's `channel.json` is used (top-left).
  Set `"watermark": ""` only to switch it off for one topic. `"theme"` overrides the channel's theme (rarely needed).
- `style: "panel"` is the older card layout (`topics/alpukat`, `topics/mandi-malam`); use `paper` for new videos.

## scenes.js API (paper style)

Define these globals:

| name | when | purpose |
|---|---|---|
| `setup(D)` | once, after timings load | compute times, then `setCamera`, `setHeadlines`, `setChapters` |
| `drawWorld(t, cam)` | every frame | the world in **world coordinates**; returns an SVG string |
| `drawOverlay(t, cam)` | every frame, optional | screen-space pieces (cards, stamps, flashes, `cite`) |
| `cues(D)` | once | sound effects `[[seconds, kind], ...]` |
| `drawThumbnail()` | `thumb` only | `{world, ui}` SVG strings for a 1080×1920 still (`ui` is above the texture: put titles there) |

**Timing.** `D.scenes[i]` has `start`, `end`, `audio`, `words`, and `at(word, delta = 0)`, which returns the
second that word is spoken (prefix match, case and punctuation ignored, first occurrence). Anchor everything
to words, never to hard-coded seconds; the voice changes length when text or provider changes.
`D.total` is the video length. Collect named times in a `K` object in `setup` (see burung-listrik).

**Camera.** `setCamera([{x, y, z}, {at, dur, x, y, z}, ...])`: the first entry is the opening view; each next
entry eases from its `at` over `dur` seconds to the new centre `(x, y)` and zoom `z` (zoom eases
geometrically). The world point `(x, y)` lands at screen `(540, 900)`. A little handheld drift is added.
For the loop, make the last key go back to the first view, starting at about `D.total - 1.5`.

**Headlines.** `setHeadlines([{at, end, text, y?, size?}])`: big outlined title (font Lilita One),
`*word*` is yellow, `\n` breaks lines, shrinks to 780 px wide, default `y` 360. Overlaps are resolved for you.
Keep them 2–4 words; they repeat the key idea, not the subtitle.

**Chapters.** `setChapters([{at, icon: () => svg}], {at, end})`: a badge top-right that changes per chapter;
during the recap window all earlier icons line up with a green check. Icons are drawn around (0,0), ~28 px.

**Sound effects** (`cues`): `pop`, `tick`, `thud`, `whoosh`, `ding`, `click`, `sparkle`, `zap`, `chirp`.
Use `whoosh` on camera moves, `pop` on things appearing, `thud` on stamps, `ding` on conclusions.
A recorded file `engine/sfx/<kind>.mp3` (or `.m4a`, `.wav`) replaces the synthesized sound of that name in every video;
its silence is trimmed and its loudness matched to the sound it replaces. Recorded now: `whoosh` (camera moves),
`pop` (a mouse click: headlines, cards, labels appearing), `ding` (conclusions) and `thud` (a deep boom: stamps, big hits).

**Helpers** (`engine/lib.js`):

| helper | use |
|---|---|
| `P(t, t0, dur, ease)` | 0→1 progress; eases in `E`: `lin`, `outCubic`, `inCubic`, `inOutCubic`, `outBack`, `outElastic` |
| `pop(t, t0, dur)` | `{s, o}` scale/opacity for popping things in |
| `G(transform, opacity, inner)`, `T(x, y, s, rot)` | group with transform / opacity |
| `stroke(w, col)`, `limb(d, w, col)` | ink stroke attrs; outlined thick path (arms, legs, wires) |
| `txt(s, x, y, size, fill, weight)` | Nunito text; `hand(s, x, y, size, fill)` Caveat handwriting |
| `titleText(text, cx, cy, size, maxW, outline)` | outlined title (headlines, thumbnails) |
| `stamp(label, t, ts, x, y, col, rot, size)` | rubber stamp that slams down at `ts` ("MITOS!", "FAKTA!") |
| `cite(text, t, t0, t1, y)` | small source pill (screen space) |
| `pill(label, x, y, size, fill, color, s, o)` | rounded label |
| `layer(d, cam, inner, anchor)` | parallax layer in world space (`d = 1` normal, `d < 1` farther) |
| `shadow(x, y, w, o)` | contact shadow adapting to the theme style (soft gradient, doodle hatching, ink) |
| `burst(t, t0, x, y, opts)` | radial rays and dots flying out (`{n, r, col, dur, size}`) |
| `confetti(t, t0, x, y, opts)` | celebratory confetti pieces with gravity and spin (`{n, spread, dur}`) |
| `dustPuff(t, t0, x, y, opts)` | drifting dust puffs (`{n, size, dur}`) |
| `impactRing(t, t0, x, y, opts)` | expanding shockwave rings (`{r0, r1, col, dur}`) |
| `speedLines(t, t0, t1, cx, cy, opts)` | anime focus speed lines in screen space (`{r, n, col}`) |
| `spotlight(t, t0, t1, x, y, r, dim)` | darkened vignette around a circle in screen space |
| `toScreen(cam, x, y)` | convert world point `(x, y)` to screen coordinates for screen-space FX |
| `impact(t, ts, k)` | camera shake and zoom punch (called automatically by `stamp`) |
| `sticker(label, t, ts, x, y, opts)` | sound word ("TIT-TIT!", "TEK!", "BZZT!") that pops on at `ts`, wobbles, pops off after `dur` (`{rot, size, col, dur, shake, lines}`); no shake by default. Pair it with a cue, 3–4 per video at most |
| `card(t, t0, x, y, w, h, inner, opts)` | info card centred on `(x, y)` in the theme's style, pops in at `t0`; `inner` is drawn from the card's top-left (`{title, tOut, col, rot}`) |
| `scramble(text, t, t0, dur, opts)` | returns `text` as random glyphs that lock in left to right from `t0` to `t0 + dur` (`{seed, rate, set}`); digits stay digits, spaces and punctuation stay |
| `mono(s, x, y, size, fill, opts)`, `monoWidth(s, size)` | text on a fixed character grid (use it for scrambled text and numbers so they don't jump; `{anchor, cell, weight}`) |
| `bodyText(s, x, y, size, fill, anchor, weight)`, `bodyFont()` | text in the theme's body font (Nunito / Oswald / Caveat), for card contents |
| `xray(t, t0, x, y, r, inside, opts)` | round lens that opens at `t0` and shows `inside` (same coordinates as the world) through a cover (`{t1, dur, id, bg}`); give each lens in a frame its own `id` |
| `hype(text, t, t0, x, y, opts)` | "hypermotion" title: slams in skewed at `t0` with a short shake, 3D extrusion, an outline echo that pulses out (`{size, tOut, skew, depth, col, shake}`). For the one or two words that must hit hardest; headlines take `{hype: true}` |
| `invertFlash(t, ts, dur)` | the whole frame flips to its negative for ~2 frames at `ts`; a hard accent, once or twice per video |
| `vol(d, fill, opts)`, `circleD`, `rectD` | draws a shape (path `d`) with volume in the theme's style: cel shadow + highlight + ink outline (paper), round gradient (newsprint), hatched shadow (notebook) (`{depth, w, shine}`). Use it for every prop instead of a flat `fill` |
| `cutaway(t, t0, shell, opts)` | lifts a cover (`shell` SVG) off from `t0` to show what is drawn under it, back from `t1` (`{t1, dx, dy, rot, dur, cx, cy}`) |
| `sparkle`, `snowflake`, `mix(hexA, hexB, p)`, `rnd(i)`, `lerp`, `clamp`, `measure` | small utilities |
| `cicak(x, y, s, pose, t, rot, walk, faceKind)` | Si Cicak (top-down view, crawls any direction with `rot`; `walk = t * 11` animates legs). See "Mascots" below |
| `face(kind, geometry, t)`, `eye`, `eyePair`, `magnifier` | shared expressions and props (`engine/faces.js`) for drawing new characters |

## Prop library (`engine/props.js`)

Reach for these before drawing a prop from scratch; they are shaded with `vol` and follow the theme. Each takes
world coordinates; plants take `t` for wind. See `topics/demo-props` (render it with `"theme"` set to see all looks).

| function | draws |
|---|---|
| `leaf(x, y, len, ang, {col, wide, veins})` | one leaf with midrib and veins, from its stalk |
| `tree(x, y, h, t, {kind: 'round' \| 'palm', seed, col, bark, fruit})` | a tree standing on (x, y): leafy crown with one outline, or a coconut palm with fronds |
| `bush(x, y, w, t, {col, flowers})`, `grass(x0, x1, y, t, {h, col, density})`, `flower(x, y, s, t, {petal, center, n})`, `rock(x, y, w)` | undergrowth |
| `woodPlank(x, y, w, h, {col})`, `ground(x0, x1, y, depth, t, {col, withGrass})` | surfaces: a board with grain and a knot, soil with pebbles and grass |
| `bulb(x, y, s, {on, t})`, `coin(x, y, s, {label})`, `banknote(x, y, s, {value, col, rot})` | lamp hanging from its base, coin with a rim, a generic banknote (never copy a real design) |
| `phone(x, y, s, {screen, col, rot})`, `glass(x, y, s, {level, liquid, t})`, `box(x, y, s, {col})` | smartphone (screen SVG in a 200×380 box), drinking glass, cardboard box |

Add a prop here (not in a topic) once two topics need it, and give it all three looks through `vol`.

## Mascots

All mascots share one API: `name(x, y, s, pose, t, rot = 0, walk = null, faceKind = null)`.

- **Poses** (`POSES`): `happy` (waves), `cheer` (both arms up), `point` (points right; mirror with a negative `s`
  in a `G('scale(-1 1)', …)` group to point left), `think` (hand to chin), `verdict` (holds a magnifier),
  `shock` (cicak drops its tail), `calm`.
- **Faces** (`FACES`): `smile`, `calm`, `laugh`, `wink`, `love`, `wow`, `sad`, `angry`, `skeptical`, `sleepy`,
  `confused`, `cool`, `shock`, `smug`. Each pose has a default face (`POSE_FACE`); pass `faceKind` to combine
  any pose with any face, e.g. `cicak(x, y, 0.5, 'point', t, 0, null, 'wow')`.
- Model sheets with every pose and face: `docs/mascots/cicak.jpg`, `tikus.jpg`, `stickman.jpg`
  (regenerate with `python make_brand.py`).

| mascot | file | channel | art style |
|---|---|---|---|
| `cicak` — Si Cicak, house gecko | `engine/cicak.js` | **@cicaktahu** (this channel) | **flat ink**: thick ink outlines, flat colours, warm paper |
| `tikus` — Si Tikus, chibi mouse | `engine/tikus.js` | another channel | **soft plush**: no outlines, gradient shading, gloss, kawaii eyes, pastel |
| `stickman` — stick figure with a green head | `engine/stickman.js` | another channel | **doodle**: wobbly double pen lines that boil 8×/s, marker fill off the outline, hatching, lined notebook |

Each channel's videos must match its mascot's style: props drawn for a Si Tikus video get soft gradients
and no ink outlines (see `topics/demo-tikus`); props for a Stickman video use wobbly pen lines that boil
(see `doodle()` in `topics/demo-stickman`). Headlines, captions, stamps, chapter badges, `cite` and the page
texture follow the channel theme by themselves (`THEMES` in `engine/lib.js`); in the newsprint theme use
stamp labels like `HOAKS` / `FAKTA` / `MENYESATKAN`. `face()` takes the art style through its geometry
(`style: 'ink' | 'soft' | 'doodle'`, `ink`, `weight`).

Use the mascot of the channel you are making the video for (`channels/<id>/channel.json` → `"mascot"`); never mix mascots
of different channels in one video. Pick faces that match the beat: `confused`/`skeptical` for the common
belief, `smug` + `stamp` for the verdict, `wow` for a surprising number, `sad`/`shock` for a danger, `laugh`
or `happy` for the ending.

Colours: use `C.*` (`ink`, `muted`, `yellow`, `accent`, `cool`, `leaf`, `line`, `bg`). Add topic colours with
`Object.assign(C, {...})` at the top of `scenes.js`. Outlines are ink, `STROKE` = 7 world units.

## Layout rules (screen space, 1080×1920)

- Progress bar (only with `"progress": true`) at the top (y ≈ 28, x 40–1040, 10 px).
- Headline ~y 280–480 (keep ≥ y 280). Chapter badge (950, 190). Captions centred at y 1500. `cite` at y 1395.
- Keep the subject between y 550 and y 1400. Below ~1600 and the right edge (x > 960, y 1000–1700) are covered
  by the YouTube Shorts UI.
- World strokes scale with zoom: at `z = 3` a 7-unit outline is 21 px. Draw close-up props a bit thinner.
- Draw every frame from `t` only (no state, no `Math.random`): frames are rendered out of order by parallel workers.
  Use `rnd(i)` for stable randomness.

## Voice providers (tts.py)

| provider | needs | word timings |
|---|---|---|
| `edge` (default) | internet | from the service |
| `azure` | `pip install -r requirements-extra.txt`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` | from the service |
| `elevenlabs` | `ELEVENLABS_API_KEY`, `"name"` = voice id | from the service |
| `file` | recordings `topics/<topic>/voice/scene1.wav`…, `faster-whisper` | Whisper, matched to the script |
| one take | `topics/<topic>/voice/full.mp3` (or `.wav`, `.m4a`…): the whole script in one recording, made anywhere (ElevenLabs, a studio, your phone); `faster-whisper` | Whisper once, matched letter by letter to the script, cut into lines in the pauses; used automatically when the file exists |

Whisper model: `WHISPER_MODEL` (default `small`), language `WHISPER_LANG` (default `id`),
device `WHISPER_DEVICE` (default `cpu`; `cuda` needs the CUDA 12 libraries).
The voice cache in `build/<topic>/tts/` is reused until the text or voice settings change.
For a one-take recording the narration must say exactly what `script.json` says (captions come from the script);
the pause between lines becomes the usual 0.35 s plus `hold`. Never put recordings in `build/` (it is regenerated).

## Troubleshooting

- `word "x" not spoken in scene`: the anchor word differs from what the voice said; check `tts/scene*.json`.
- `fonts did not load`: `engine/fonts/` is missing files.
- Browser fails to start on Linux: run `python -m playwright install --with-deps chromium`;
  pick another browser with `BROWSER_CHANNEL=chromium|msedge|chrome`.
- Out of memory: lower `workers=`.
